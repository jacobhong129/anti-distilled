# 抗蒸性测试 V10.10：完整游戏设计与开发说明

## 1. 产品定位

产品名：

> 抗蒸性测试：测测你的含活人量

一句话：

> 用一个半开玩笑、半专业的自适应问答游戏，测出你在 AI 时代有多难被蒸馏成一个同事 Skill。

核心体验：

- 用户不是做固定 24 题，而是被系统动态追问。
- 越清楚、越低摇摆的人越快结束；越复杂、越难蒸、越接近分段边界的人必须多问几题。
- 结果不是人格分类，而是“含活人量 + 抗蒸段位 + 结构标签 + 六维剖面 + 成长提示”。

V10.10 的历史问题复盘与应用开发准入见 `docs/v10.10-historical-regression-and-app-readiness.md`。

## 2. 设计原则

1. 有趣，但不装神秘。
2. 专业，但不写成量表考试。
3. 低分可以调侃，但不能羞辱。
4. 高分必须经过反证，不能靠漂亮答案刷出来。
5. 可 Skill 化不是低价值；“可教不好替”是高价值结果。
6. 结果显示 0-100%，但解释上不宣称 1% 精密诊断。

## 3. 游戏流程

### 3.1 开始页

目的：

- 解释“含活人量”是什么。
- 说明题量是动态的。
- 降低用户对低分的焦虑。

建议文案：

> 这不是测你会不会被 AI 替代。  
> 这是测你的判断、经验、审美和取舍，有多难被低损耗蒸馏成一个同事 Skill。

辅助文案：

> 大多数人 18 题左右完成。越难蒸，系统可能会多追几题。

按钮：

> 开始蒸馏

### 3.2 初筛阶段

题量：

- 固定 8 题。

目的：

- 建立六维初始画像。
- 判断可 Skill 化、表达转译、噪声风险和工具边界。

前台提示：

> 先闻一闻大概人味。别想太多，选最像你平时反应的那个。

进度展示：

- 不展示“第 1/24 题”，避免用户以为固定题量。
- 推荐显示：`初筛中 1/8`

### 3.3 动态追问阶段

题量：

- 常见 6-12 题。
- 默认从第 16 题开始允许结束；14 题只作为极少数低摇摆例外。
- 最多 24 题。

目的：

- 确认强弱维度。
- 区分相似标签。
- 处理虚高风险和误伤风险。

前台提示文案池：

| 场景 | 文案 |
|---|---|
| 初筛结束 | 初步闻到一点人味了，接下来确认几个关键处。 |
| 维度摇摆 | 你的回答出现了两种可能，我们换个场景看一下。 |
| 高分验证 | 这里有一点不可压缩判断，系统想再追一下。 |
| 噪声验证 | 这题不是怀疑你，是防止把“说不清”误判成“很深刻”。 |
| 题量变多 | 你比较难蒸，系统需要多烧一会儿。 |

进度展示：

- 推荐显示动态状态，不显示固定总题量：
  - `正在确认边界`
  - `正在追踪直觉来源`
  - `正在排除伪抗蒸`
  - `画像快稳定了`

### 3.4 结束判断

最少题量：

- 14 题。

常见结束：

- 17-19 题。

最多：

- 24 题。

停止条件：

默认从第 16 题开始，每 2 题检查一次。满足以下 5 条中的 3 条才可结束：

1. 含活人量分段连续两轮不变。
2. 第一结构标签连续两轮不变。
3. 第一标签与第二标签置信度差距大于 0.18。
4. 当前最高风险误判已经被反证题处理。
5. 主标签证据覆盖达标。

14 题提前结束只作为例外，必须画像非常稳定、证据完整、没有开放风险，并且不是复杂或高潜用户。

复杂用户最少 18 题。包括 55-79 分中高段、关键标签候选、Top2 标签差距不足、GEN/BND/TLB 明显偏高等情况。

20 题前如果出现标签摇摆、分段大幅变化、靠近段位边界、高潜标签未反证、伪抗蒸风险未处理、中段未分叉、老练直觉缺来源证据等情况，不允许结束。

结束提示：

> 画像稳定，可以出锅。

如果 24 题仍摇摆：

> 你的画像有一点摇摆：系统更确定你的强项，但对你的表达方式还保留一点疑问。

## 4. 结果页结构

结果页由 5 层组成。

### 4.1 含活人量

展示：

> 含活人量：82%

解释：

> 这是你的抗蒸展示分，用来表示你的判断、经验、审美和取舍被低损耗复制的难度。

禁止文案：

> 你比 82% 的人更难被 AI 替代。

### 4.2 抗蒸段位

| 分数 | 段位 | 一句话 |
|---|---|---|
| 90-100 | 真人浓缩型 | 你不是不能被总结，而是一总结就会少一个人。 |
| 80-89 | 关键真人型 | 你的方法能学，但关键判断很难外包。 |
| 70-79 | 高损蒸馏型 | 你的流程能抄，真正值钱的地方会在例外里漏出来。 |
| 62-69 | 招牌养成型 | 你有自己的判断，不过有时还没强到让复制品明显失真。 |
| 55-61 | 半蒸半活型 | 一部分很适合沉淀成 Skill，一部分还需要你本人在场。 |
| 45-54 | 协作易蒸型 | 你的稳定和清楚是优点，但还需要长出更鲜明的判断。 |
| 35-44 | 流程友好型 | 你现在最稳定的价值来自流程、标准和执行。 |
| 20-34 | 优质蒸馏原料 | 你很可靠，也确实有点好蒸；下一步是把经验变成判断。 |

### 4.3 结构标签

结构标签解释“含活人量来自哪里”。

主要标签前台展示名：

- 可教不好替
- 老练直觉
- 边界感
- 空话免疫
- 改题型
- AI 放大型
- 有底线型
- 慢表达品味型
- 伪抗蒸型
- 待开机型

结果页显示：

- 主标签 1 个。
- 辅助标签 1 个，可选。
- 如果标签摇摆，显示“画像有摇摆”提示。

### 4.4 六维剖面

展示六个核心维度：

- 情境辨识
- 边界校准
- 生成重构
- 审美判别
- 价值定向
- 经验内化

每个维度显示：

- 分数条。
- 1 句解释。
- 是否为强项、待发展项或摇摆项。

### 4.5 成长提示

结果页最后给一个正向建议：

- 高分用户：训练表达转译，把不可替代变成影响力。
- 中分用户：找到最强维度，练成稳定招牌。
- 低分用户：从“我为什么这样做”开始，把执行经验变成判断。
- 伪抗蒸用户：不是更特别，而是更能说明依据。

## 5. 数据结构

完整开发配置：

> `config/game-config-v10.10.json`

配置包含：

- 游戏标题。
- 10 个计分指标。
- 8 个结果段位。
- 结构标签字典和前台人话解释。
- 岗位蒸馏度模块。
- 含活人量公式。
- 动态抽题规则。
- 120 道题。
- 480 个选项。
- 每个选项的计分向量、证据标签和标签置信度变化。

每道题的核心字段：

```json
{
  "id": "SCREEN_08",
  "stage": "screening",
  "role": "screen",
  "primaryMetric": "TLB",
  "secondaryMetrics": ["STN", "SKL"],
  "question": "...",
  "topicTags": ["ai_tool", "screen"],
  "options": [
    {
      "key": "A",
      "text": "...",
      "type": "process_execution",
      "scores": {"SKL": 2},
      "evidence": ["standardizable_work"],
      "labelDelta": {}
    }
  ]
}
```

V10.5 选项展示要求：

- 前台不显示 A/B/C/D。
- 前台使用每题的 `presentationOrder` 渲染。
- 可按 session seed 做稳定打乱。
- 后台仍记录原始 `option.key` 计分。
- 目的：避免用户把某个顺位理解成固定高分或固定低分。

V10.6 职业因素要求：

- 可选收集“岗位蒸馏度”。
- 岗位蒸馏度不直接加减个人含活人量。
- 结果页应区分“你这个人有多难蒸”和“你当前工作方式有多容易被蒸”。

## 6. 核心算法

### 6.1 每题后更新

用户每答一题，系统更新：

- 原始指标分。
- 每个指标可得总分。
- 标准化指标分。
- 证据标签。
- 结构标签置信度。
- 误判风险。
- 下一题候选池。

### 6.2 标准化指标分

因为每个用户题量不同，不能直接比原始分。

```text
metric_score = earned_points / possible_points_for_answered_items * 100
```

### 6.3 含活人量

```text
core_score =
  CXT * 0.16 +
  BND * 0.20 +
  GEN * 0.16 +
  TST * 0.15 +
  STN * 0.16 +
  GRD * 0.17

display_score =
  clamp(
    core_score +
    EXP * 0.08 +
    TLB * 0.05 -
    max(0, SKL - average(BND, CXT, GRD, EXP)) * 0.12 -
    NOI * 0.16,
    20,
    98
  )
```

### 6.4 下一题选择

候选题优先级：

```text
priority =
  low_confidence * 0.40 +
  label_impact * 0.30 +
  contradiction_risk * 0.20 +
  topic_freshness * 0.10
```

约束：

- 不重复已答题。
- 避免连续 3 道相同场景标签。
- 初筛必须覆盖六维。
- 高分路径必须至少有 1 道反证题。
- 标签置信度差距小于 0.18 时，优先出分叉题。

## 7. 开发页面清单

### 7.1 页面

| 页面 | 功能 |
|---|---|
| Start | 开始页，解释含活人量和动态题量 |
| Question | 答题页，展示题干、选项、动态状态 |
| Thinking | 短暂过渡页，可展示“正在追踪不可压缩判断” |
| Result | 结果页，展示分数、段位、标签、六维、建议 |
| Share | 分享页或截图态 |

### 7.2 答题页状态

| 状态 | 说明 |
|---|---|
| screening | 初筛中 |
| confirming | 维度确认中 |
| splitting | 画像分叉中 |
| counterchecking | 反证中 |
| stable | 可以结束 |
| forced_done | 达到 24 题强制结束 |

### 7.3 结果页模块

1. 分数大字。
2. 段位标题。
3. 一句话结果。
4. 主结构标签。
5. 六维条形图。
6. 系统为什么这么判。
7. 成长建议。
8. 分享短句。

## 8. 埋点与测试

### 8.1 用户行为埋点

| 事件 | 字段 |
|---|---|
| test_start | session_id, timestamp |
| question_view | item_id, stage, position |
| option_select | item_id, option_key, scores, evidence |
| adaptive_step | reason, candidate_count, selected_item_id |
| test_stop | answered_count, stop_reason |
| result_view | score, band, top_label, confidence |
| share_click | score, band, label |

### 8.2 质量监控指标

| 指标 | 预警 |
|---|---|
| 平均题量 | 大于 20 题需要调停止规则 |
| 强制 24 题比例 | 大于 15% 说明题路不够收敛 |
| 单选项选择率 | 某选项超过 55% 需审题 |
| 结果集中度 | 50-60 分超过 45% 需调权重 |
| 伪抗蒸高分率 | P05/P12 型高于 75 分需修正 |

## 9. MVP 开发范围

第一版建议：

- 使用 `game-config-v10.10.json` 驱动前端。
- 动态抽题先用规则版，不上机器学习。
- 结果页先展示 5 层结果，不做复杂社交图谱。
- 本地存储或 session 内存即可，不需要账号。
- 先支持虚拟人测试和小规模真人测试。

暂不做：

- 用户历史档案。
- 排行榜。
- 真正的百分位比较。
- LLM 动态生成题目。
- 复杂动画和过度游戏化包装。
