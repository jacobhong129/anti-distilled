# 虚拟用户评测 V4

## 测试目的

用 `question-bank-v4-expanded-readable.md` 的 36 题和 `scoring-table-v4.csv` 的分值表，模拟 6 类典型用户，观察扩容后的评分体系是否仍能保持：

- 初心一致：奖励复杂判断，而不是奖励“怪”。
- 差异化：不同用户能拉开分数。
- 友好性：低分不等于羞辱，高分不等于神化。
- 可解释性：分数差异能从六维和辅助因子里解释。

## 观察

V4 评分能拉开最重要的差异：

- U3 最高，因为它不是“最独特”，而是六维均衡、锚点全中、噪声为 0。
- U4 的正向原始分比 U2 高，但含活人量被噪声和低健康表达压低，符合“直觉强但不稳定”的定位。
- U5 的六维正向分不低，但噪声率 95%，含活人量只有 34，说明伪抗蒸机制有效。
- U1 的 Skill 适配度为 80，说明稳定、清楚、可复用被保留为优势，而不是被简单羞辱。

## 发现的问题

### 1. 当前公式偏保守

U3 这种理想的复杂判断型用户，含活人量只有 73。作为产品体验，这会让高分用户缺少成就感。

这不是题目区分度问题，而是展示分数校准问题。当前公式更像“原始测量分”，不是“用户可感知分”。

建议增加展示分校准：

```text
if raw_human_score <= 0.05:
  display_score = 18
else:
  display_score = clamp(round(20 + raw_human_score * 85), 20, 100)
```

这个校准会让：

- 极低分仍保留调侃空间，不显示冰冷的 0。
- 中分用户更接近直觉上的 55-65。
- 高分用户更容易进入 80+，获得成就感。

### 2. U2、U4、U6 中间层略拥挤

U2、U4、U6 的含活人量分别是 49、48、46，差距偏小。但三者画像其实差异很大：

- U2 是健康表达高、Skill 适配度高。
- U4 是经验直觉强、噪声高、Skill 适配度低。
- U6 是专业协作稳定、生成性弱。

建议结果页不要只依赖一个总分，要结合：

- 六维最高项
- Skill 适配度
- 噪声提示
- 健康表达

这样同分附近也能产生不同解释。

### 3. 题库扩容后更需要“标准版/完整版”

36 题更能覆盖维度，但真实用户可能会觉得略长。建议产品上做两种入口：

- 标准版：24 题，每章抽 4 题。
- 完整版：36 题，命名为“深度蒸馏检测”。

## 结论

V4 已经能支持一个更完整的评测游戏：

- 题量更复杂。
- 语言更可读。
- 题目节奏更清楚。
- 六维更独立、更容易解释。
- 噪声机制仍能压住“伪抗蒸”。

下一步应该做 V4.1：

1. 将 `scoring-matrix-v4.md` 补充分数校准规则。
2. 对 U2、U4、U6 这类中间层用户设计不同结果文案。
3. 从 36 题里抽出 24 题标准版，方便真实用户先试。
